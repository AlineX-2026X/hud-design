# 三种 HUD 与实拍 / 引擎内嵌

同一套视觉语言放进真实画面，会分成三种存在方式：

| 模式 | 定义 | 需要补什么 | 画面中样本 |
|---|---|---|---|
| screen-space | 贴在最终画面平面，不随物体转动 | 景深、亮度衰减、与镜头一致的抖动 | 驾驶舱、医疗屏、数据屏 |
| world-space | 锚定三维物体或空间坐标，随镜头透视变化 | 锚点、深度排序、遮挡、透视贴合 | 车身引线、透明卡 |
| diegetic | 世界内的实体设备（腕投、舱屏、手机），角色可看见 / 触摸 | 物理痕迹 + 交互因果 + 设备身份（编号 / 品牌） | 腕投面板、驾驶舱、手机 |

三条硬规则：

1. **模式必须选一个并给叙事理由**。说清「谁在看、从哪看、为什么能看到」，「看起来酷」不是理由。
2. **diegetic 要保留物理痕迹**：玻璃反射、灰尘、手部遮挡、投影倾斜、亮度随环境光变化。缺了这些，观众立刻识别为后期贴纸。
3. **后期要匹配**：bloom、色差、噪点、镜头畸变、景深必须与实拍同量级；HUD 不能比素材更「干净」。

引擎内还有一层：开发标注与真机测试。成熟流程会在真实运行环境里测，而不是只在合成软件里看。

## 步骤

1. 写一句「谁在看」：角色 / 摄像机 / 观众，据此定模式。
2. 选锚点：屏幕、物体表面、设备；给位置、朝向、可动范围。
3. 定变换：缩放随距离、透视随角度、遮挡规则（前景优先）。
4. 加物理痕迹：从反光、灰尘、倾斜、光晕、噪点中选 ≥3 种并给强度。
5. 接后期：bloom、色差、噪点、景深与实拍同量级，检查 HUD 不比素材更干净。
6. 加叙事状态：载入、失败、越界、拒绝。
7. 验收：最终镜头角度与距离下 25% 缩略仍可读关键值；遮挡后不误导；关掉 HUD 画面仍成立；观众能说出「这块屏属于谁」。

输出：模式选择 + 锚点 / 变换参数 + 物理痕迹清单 + 后期参数 + 验收记录。

## 样例

一块腕投全息：界面从角色腕部设备投出而非贴在镜头前——面板随手臂角度倾斜、随距离缩放，带边缘光晕与设备编号，靠近操作后才展开 `ENZYME CONTROL` 与进度。改成 screen-space 贴片会立刻失去「这是她手臂上的设备」这层信息——**模式选择本身就是叙事**。

## 边界

- 同一镜头不要混用三种模式而不给理由（除非剧情明确要求「界面叠界面」）。
- diegetic 不等于更真实：它牺牲可读性，关键信息仍要有 screen-space 兜底（字幕 / 提示）。
- AR / 车载涉及安全与法规，影视手法不可直接移植。
- 画面中品牌屏、影视道具屏只能作方法参考，不能复用其视觉资产。
