# HUD 诊断与优化：六轴审计与 P0/P1/P2 修复单

优化不是「再酷一点」，而是**按任务读取效率排优先级，逐条消除噪声**。

## 一、六轴

每一轴都有可观察的失败信号与对应修法：

1. **可读性**：25% 缩略与灰阶下还能不能读；字号、对比度、发光溢出、背景干扰。
2. **层级**：3 秒内能否定位「状态 / 动作 / 风险」；是否只有一层最亮最大。
3. **密度节奏**：是否全屏均匀密度；净空是否被装饰填满；密区是否有标题与分隔。
4. **语义色彩**：告警色是否只用于异常；是否颜色 + 形状 + 文字三重编码；色觉障碍下是否仍可区分。
5. **动效**：循环动画数量、时长是否过长、是否用循环闪烁代替一次性强调、是否整屏重绘。
6. **集成与性能**：透视 / 反光 / 遮挡是否成立；半透明叠层与 bloom 是否过量；空 / 载入 / 失败 / 越界是否齐备。

输出按 **P0（影响读取关键值或安全）/ P1（影响效率与可信度）/ P2（打磨）** 排序，每条写「证据 → 影响 → 修法 → 验收方式」。交付的是可执行修复单，不是审美评论。

## 二、输入契约

| 字段 | 要求 |
|---|---|
| 材料 | 截图（≥1920 宽）/ 录屏（≥10s）/ 可运行构建 |
| 场景 | 谁、在什么环境、什么距离、看多久 |
| 任务 | 这块屏必须支撑的 1–3 个决策；缺失时先问，否则只能做「视觉层」审计并声明 |
| 约束 | 品牌、引擎、分辨率、是否色觉无障碍要求 |
| 界面显示语言 | 不填则跑 `scripts/detect-language.sh` 自动探测；填了以填的为准 |

## 三、界面显示语言（自动探测，先于审计）

```bash
bash scripts/detect-language.sh     # 输出 zh-CN / zh-TW / en
```

审计报告与修复单默认用探测结果对应的语言写；用户显式指定则覆盖。macOS 读 `AppleLocale`，Windows 在 Git Bash 下读 `Get-Culture`、在原生 cmd / PowerShell 下改用 `scripts/detect-language.ps1`，Linux 读 `LC_ALL` / `LANG` 与系统 locale 配置，WSL 借用 Windows 区域，鸿蒙走 `param get persist.sys.locale`。

| 探测结果 | 报告语言 | 对该屏语言一致性的判据 |
|---|---|---|
| `zh-CN` | 简体中文 | 除机器标识外应为中文；单位用中文词 |
| `zh-TW` | 繁體中文 | 同上，繁体字形 |
| `en` | English | 除专有名词外应为英文；全大写 + 宽字距 |

它同时是审计项：**同一块屏混用两种自然语言**（「Fuel System」与「燃料系统」并列）记 P1——不是风格问题，是读取效率问题。机器标识与专有名词（`HEADER 273`、`HUD`、`task_id`）不算违反。

## 四、步骤与完成标准

1. **建基线**：记录分辨率、观看距离、任务、关键值清单。缺任务则声明「仅视觉审计」。
2. **可读性**：缩到 25%，再转灰阶，标记仍可读与消失的元素。关键值在两档下都可读；正文对比度 ≥4.5:1、大字 ≥3:1。
3. **层级**：做 3 秒测试，说出状态 / 动作 / 风险，记录第一眼落点。三项都能说出；最亮元素就是关键项。
4. **密度节奏**：统计净空占比、同级模块数、无标题密区。净空 ≥30%；每个密区有标题与分隔；关键项 ≤5。
5. **语义色彩**：统计告警色像素占比与用途，检查三重编码与色觉替代。占比 ≤5% 且只用于异常 / 危险 / 选中；每个告警都有形 + 字冗余。
6. **动效**：录屏统计循环动画数、单段时长、是否整屏重绘。同时循环 ≤2；状态动画 ≤240ms；强调只出现一次。
7. **集成与性能**：检查透视 / 反光 / 遮挡 / 噪点；统计同像素叠层与 bloom 面积；列状态完备性。diegetic 至少 3 种物理痕迹；叠层 ≤4；空 / 载入 / 失败 / 越界 / 无权限全覆盖。
8. **排优先级**：每条归档 P0 / P1 / P2。P0 ≤5 条，且每条能指向具体像素或时间点；修法不要求整体重做（除非 P0 >3）。

括内数值为工程约定，不是画面里的实测数据，换引擎或平台需按实测调整。

## 五、输出契约

| 轴 | 证据（时间点 / 区域） | 影响 | 修法 | 验收 | 优先级 |
|---|---|---|---|---|---|

附三项：`结论`（一句话）、`不改什么`（明确保留的优点）、`未决项`（缺信息无法判断的部分）。

## 六、样例（引擎内 UI 卡片系统测试）

| 轴 | 证据 | 影响 | 修法 | 验收 |
|---|---|---|---|---|
| 可读性 | 键盘 UI 占满画面，键帽文字与边框亮度接近 | 找不到功能键区，输入效率低 | 按「功能键 / 字母 / 空格」分三区，功能区提高一档亮度 | 25% 缩略下一眼分出三区 |
| 层级 | 开发标注与 HUD 元素同亮度、同字体 | 被误读为界面状态 | 标注降到 15% 亮度或移出录制区 | 灰阶下标注不进前三亮 |
| 密度节奏 | 径向舰桥控制台同屏 20+ 标签、无净空 | 分不清操作与读数 | 按操作频率分三层：常驻 / 次级 / 折叠 | 常驻项 ≤7 |
| 语义色彩 | 红色 `NO ENTRY` 语义正确，但红色同时用于装饰描边 | 告警色被稀释 | 装饰描边改低饱和同色相 | 告警色像素 ≤5% |
| 动效 | 以静态为主，无循环轰炸 | 无 P0 | 保持「进入一次、静止停留」 | 10s 内循环 ≤1 |
| 集成与性能 | 已在引擎内验证 | 可信度较高 | 补 overdraw 统计 | 帧率与叠层预算达标 |

结论：这是「结构正确、打磨未完成」的屏，P0 只有一项。审计应先保护读取，再谈风格。

## 七、边界

- **没有场景与任务时不下「可用性结论」**：只能给视觉层意见，并声明局限。
- **不用影视审美替代可用性**：`ANOMALY` 横幅在电影里 2 秒有效，在工具里可能需要常驻可查。
- **不默认整体重做**：P0 ≤3 时优先局部修复；重做建议必须给成本与风险。
- **不评价作品版权与美术风格归属**：只审设计与工程，不做艺术评判。
- **不适用于**：纯品牌页、平面海报、Logo、无数据主体的装饰性动画。
- **性能数字是约定**：叠层 ≤4、告警占比 ≤5% 等为可执行阈值，不是画面里的实测数据。
