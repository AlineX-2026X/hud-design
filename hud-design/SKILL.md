# HUD 设计全流程：从任务清单到可验收的设计包

核心判断：**先可读，再可信，最后才好看**。顺序反了，得到的是能截图传播、但不能用的屏。

## 一、七层方法

1. **决策清单**：这块屏要让人在 3 秒内回答哪 3 个问题——当前状态、下一步动作、风险。答不出来就不开工。
2. **分区**：顶栏（全局状态 / 时间）、左轨（输入与环境）、右轨（清单与日志）、中央舞台（3D 主体 + 锁定框）、底栏（操作与资源）。中央必须留净空。
3. **数据清单**：每个数据点标层级（环境 / 上下文 / 关键）、编码形式（数值 / 条形 / 圆环 / 图标 / 表格）、刷新频率、精度、告警阈值。
4. **视觉 token**：一个主色相 + 一个告警色 + 深底；三级亮度；三级字号 + 单位字号；角标代替完整边框；介质痕迹 ≤3 种。
5. **组件库**：8–12 个参数化 widget（条形、圆环、表盘、表格行、锁定框、引线、告警条、状态点、微型图表、时间码），可调尺寸 / 数量 / 角度 / 量程。
6. **动效时间线**：进入（画框 → 错峰 → 滚动 → 锁定）、状态（只动变化项）、常态（低幅呼吸）、强调（一次性）。
7. **集成与验收**：选 screen / world / diegetic，补物理痕迹，用 3 秒、灰阶、缩略、色觉、状态完备性、性能预算收口。

**可复用组件库是「看起来复杂但不乱」的前提**：画面中的成熟成品都靠同一套环形仪表、表格行、锁定框在多个镜头复用，只改参数。

## 二、输入契约

缺一项就先问，不可静默默认。

| 字段 | 要求 |
|---|---|
| 项目类型 | 影视镜头 / 游戏运行时 / 实时可视化 / 工业大屏 / 车载 / AR |
| 主体 | 3D 对象或数据模型（车、设备、地图、人体、抽象数据） |
| 用户任务 | ≤3 条，必须能写成「看见 X → 决定 Y」 |
| 交付形态 | 静态单屏 / 动态镜头 / 可交互运行时 |
| 运行环境 | 分辨率、观看距离、引擎或合成软件、是否移动端 |
| 约束 | 品牌规范、世界观设定、安全 / 法规要求 |
| 界面显示语言 | 不填则跑 `scripts/detect-language.sh` 自动探测；填了以填的为准 |

## 三、界面显示语言（自动探测，先于一切视觉决策）

```bash
bash scripts/detect-language.sh     # 输出 zh-CN / zh-TW / en
```

| 探测结果 | 显示语言 | 排版随之调整 |
|---|---|---|
| `zh-CN` | 简体中文 | 不加大字距（宽字距会把汉字拆散）；字号地板比英文模式 +1px；单位用中文词（公里/秒、毫秒、%）；全大写规则不适用 |
| `zh-TW` | 繁體中文 | 同上，用繁体字形与台港用词 |
| `en` | English | 全大写 + 字距 0.1–0.2em；单位用 SI 缩写（km/s、ms、%） |

优先级：**用户显式指定 > `HUD_LANG` 环境变量 > 系统界面语言 > `en`**；「界面显示语言：English」这类指令直接覆盖探测结果；`HUD_LANG=auto` 等同未指定。

系统覆盖：macOS（`AppleLocale`，回退 `AppleLanguages`）、Windows（Git Bash / MSYS2 / Cygwin 走 `Get-Culture`；原生 cmd / PowerShell 用 `scripts/detect-language.ps1`）、Linux（`LC_ALL` / `LANG` / `LANGUAGE` / `/etc/locale.conf` / `/etc/default/locale` / `localectl`）、WSL（借用 Windows 区域）、鸿蒙与 OpenHarmony（`param get persist.sys.locale`，手机 / 平板 / PC 同一套）。

只翻译给人看的文字——模块标题、状态词、告警词、单位、时间码标签、图例、按钮。不翻译代码标识符、API 字段名、文件路径、品牌名、`task_id` 这类机器标识。

硬规则：**同一块屏只允许一种自然语言**。中英混排只保留机器标识与专有名词（`HEADER 273`、`HUD`、`FUI`），不得把「Fuel System」与「燃料系统」同时摆上屏。

## 四、步骤与完成标准

1. **写决策清单**：产出 3 条「状态 / 动作 / 风险」句式。每条都要能指出屏上哪一处承载它，指不出的删掉。
2. **画五区骨架**：标出每区模块数量。中央舞台净空 ≥ 画面 35%；任一区不超过 3 个同级模块。
3. **建数据清单**：逐项标注层级、编码、单位、量程、刷新率、精度、异常阈值。关键层 ≤5 项/屏；每个关键项都有告警阈值与越界呈现；无无意义字段。
4. **定视觉 token**：主色相、告警色、底色、三级亮度（100 / 55 / 22）、三级字号 + 单位字号、字距、边框语言、介质痕迹。去掉颜色后仍能分出三层；告警色只出现在异常 / 危险 / 选中。
5. **列组件库**：8–12 个 widget，逐个写参数（尺寸、数量、量程、角度、状态）。同一 widget 至少覆盖 2 个不同模块；改一个参数不需要重画。
6. **排动效时间线**：进入 0–400ms（画框 → 错峰 40–80ms → 数值滚动 → 锁定）；状态 120–240ms；常态 2–4s 低幅循环（透明度变化 ≤5%）；强调只做一次。时间线是毫秒级表格；同一时刻并发动画 ≤3。
7. **定集成模式**：screen / world / diegetic 三选一并写理由；给锚点、透视、遮挡与交互因果。diegetic 至少 3 种物理痕迹（反光、倾斜、遮挡、噪点、色差）。
8. **验收**：3 秒测试、灰阶测试、25% 缩略、色觉测试（去红绿）、状态完备性（空 / 载入 / 失败 / 越界 / 无权限）、性能预算（同像素叠层 ≤4）。6 项全过；未过项写进未决清单，不带入交付。

括号内的数值是为可验收而设的工程约定，画面中没有实测数据，换平台需重新标定。

## 五、输出契约（一份 HUD 设计包）

1. `HUD Brief`：类型、主体、3 条任务、环境、约束
2. `Zone Map`：五区骨架 + 每区模块清单
3. `Data Inventory`：字段 / 层级 / 编码 / 单位 / 量程 / 刷新 / 阈值
4. `Design Tokens`：色 / 字 / 亮度 / 边框 / 痕迹
5. `Component List`：widget + 参数 + 复用位置
6. `Motion Timeline`：毫秒表 + 并发上限
7. `Integration Spec`：模式 / 锚点 / 物理痕迹 / 后处理
8. `Acceptance Record`：6 项测试结果与未决项

## 六、边界

- **不用于普通产品 UI**：App、官网、SaaS 后台、营销页、Logo、海报。信息结构不同，硬套会得到「很科幻但没人会用」的界面。
- **不用于假数据造专业感**：数据只是画面装饰时（画面中大量 `HEADER 273` 式字段），只能用于影视 / 概念，不能标称为「数据产品设计」。
- **不跳过决策清单**：直接配色与发光，是这类素材最容易误导人的地方——它展示的全是完成品，看不到「没想清楚就开画」的代价。
- **不与 `hud-audit` 混用**：已有界面先诊断，再决定是否重做。
- **场景不适配**：户外强光、车载驾驶、政务公开大屏、打印 / 投影需要更亮的底、更少发光、更严格的字号与法规校验，必须另加可用性评估。
- **无 3D / 实时主体时**：改用常规仪表盘或数据可视化规范，不必强行做空间语法。

## 七、依据

> `ENGINE DIAGNOSTIC TOOL /READY` · `FUEL SYSTEM` · `FLIGHT ORBITAL PATHS` · `HEADER 273` —— 工程仪表屏上的模块标题
> `3D ADJUSTABLE WIDGETS, REAL GEOMETRY` · `ADJUST TIME AND KEYFRAMES` —— 制作花絮里的画面字幕

素材无解说、无设计推演，以上方法系从成品画面反推。画面中未展示需求与验收阶段，本技能把这两步作为工程约定补齐。
